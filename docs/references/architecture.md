**Scope.** What the best open-source Tauri, Rust and React projects do, and what Deino should adopt for the plan in `docs/PARITY_PLAN.md` §0–§4 and cards FND-02/03/04/06/07/08/09/10/12/13.

## 0. Baseline: what Deino has today (verified)

- **Single Rust crate.** Everything is in `deino/frontend/src-tauri/src/`, and the workspace only adds `llama-helper` (`deino/Cargo.toml`, edition 2021, rust-version 1.77).
- **One command list.** `lib.rs` is 868 lines, and about 190 commands sit in a single `tauri::generate_handler![]` (`deino/frontend/src-tauri/src/lib.rs:612`).
- **State and errors.** State is one `AppState { db_manager }` (`src/state.rs`). Errors are mostly `String` or `anyhow`. `thiserror` is only used by Parakeet.
- **Capabilities** live inline in `tauri.conf.json`. `build.rs` calls plain `tauri_build::build()` (`deino/frontend/src-tauri/build.rs:24`).
- **SQL is runtime-checked.** It uses sqlx 0.8 with runtime `sqlx::query_as(...)` (about 50 call sites) and no `.sqlx` offline data. The repositories are in `src/database/repositories/*.rs`.
- **Large summary files.** The summary stack has 900–1,100-line files (`summary/service.rs`, `summary/llm_client.rs`, `summary/processor.rs`).
- **Frontend.** Next 14 `output: 'export'` with a webpack ProseMirror alias hack (`deino/frontend/next.config.js`). ESLint is only `next/core-web-vitals`, tsconfig only has `strict`, and Tailwind is v3. There are 171 TS files (31k lines), with files up to 1,408 lines (`components/ModelSettingsModal.tsx`).
- **Typed bindings.** None today. There is no specta or ts-rs.

The gap is wide, so the foundations below should be set once and copied by every card.

## 1. Workspace and crate layout

### Best found

- **anarlog** has two tiers: Tauri-free `crates/*` and thin Tauri transport `plugins/*`.
  - It has about 150 crates and about 45 plugins (`refs/anarlog/Cargo.toml` members `crates/*`, `plugins/*`; `refs/anarlog/AGENTS.md`).
  - **Plugins are thin wrappers over crates.** `refs/anarlog/plugins/template/Cargo.toml` depends on `anlg-template-app`, `anlg-db-app` and `anlg-summary`, and its commands only translate.
  - **Interface crates hold traits for dependency inversion.** See `refs/anarlog/crates/calendar-interface`, `audio-interface`, `notification-interface`, `download-interface` and `owhisper-interface`.
  - **Real and mock implementations are chosen at the composition root.** `refs/anarlog/crates/audio/src/lib.rs:79` defines `trait AudioProvider`. It is implemented by `crates/audio-actual` and `crates/audio-mock`, and the choice is made in `refs/anarlog/apps/desktop/src-tauri/src/lib.rs:92` (`create_audio_provider`, which reads `MOCK_AUDIO`).
  - **Database substrate split by single responsibility.** `db-core` handles open, pragmas and pool. `db-migrate` runs migrations. `db-app` holds schema and row operations. `db-change` sends commit-hook signals. `db-reactive` runs live queries. `plugins/db` is transport only. Each has an AGENTS.md stating "Owns / Does Not Own / Invariants" (`refs/anarlog/crates/db-core/AGENTS.md`, `crates/db-app/AGENTS.md`, `plugins/db/AGENTS.md`).
  - **Plugin anatomy** (`refs/anarlog/plugins/settings/`):
    - `build.rs` lists `COMMANDS` for ACL generation.
    - `src/lib.rs` builds a `tauri_specta::Builder` with `.plugin_name(..)`, and `init()` returns `TauriPlugin`.
    - `src/ext.rs` adds a `SettingsPluginExt` trait on `Manager`, so Rust callers do `app.settings().load()`.
    - `permissions/default.toml` holds the default permissions.
    - `js/bindings.gen.ts` is generated by a `#[test] export_types`.
  - **Cost: a lot of boilerplate per plugin.** Each needs its own `package.json`, JS dir, permissions file, a Cargo.toml that depends on `tauri`, and a `capabilities/default.json` edit (`refs/anarlog/plugins/AGENTS.md`, `.agents/skills/add-plugin/SKILL.md`). This pays off for a 10-person team with mobile and CLI targets. For a single app it is overhead.
- **spacedrive** has a Tauri-free `core` crate (`sd-core`) with CQRS and DDD (`refs/spacedrive/core/AGENTS.md`).
  - **Operations as folders.** Each operation is `core/src/ops/<area>/<verb>/{action.rs,input.rs,output.rs,mod.rs}`; see `refs/spacedrive/core/src/ops/tags/create/`, where every file is 7–83 lines.
  - **Self-registration.** Each operation registers itself with an `inventory` macro, `register_library_action!(CreateTagAction, "tags.create")` (`refs/spacedrive/core/src/infra/wire/registry.rs:594`), so there is no central list to merge-conflict on.
  - **Thin Tauri shell.** The app (`refs/spacedrive/apps/tauri/src-tauri/src/main.rs`) is a client of the daemon. It is still 2,207 lines, so don't copy that file.
  - `default-members` keeps the heavy GUI out of `cargo check` (`refs/spacedrive/Cargo.toml`).
- **Cap** is many `crates/*` for media plus a 11,109-line `apps/desktop/src-tauri/src/lib.rs`.
  - That file is the anti-pattern: no modular command registration.
  - The good part is `crates/workspace-hack` (cargo-hakari) for compile times.
- **Handy** is a single crate with `commands/`, `managers/` and `audio_toolkit/` directories, and a 1,128-line `lib.rs`. It is a simple baseline, not a model.
- **zed** has 249 small, single-purpose crates. The layering is strict: the `*_core` crate has no UI, the `api` crates hold wire types, and the adapter crates hold integrations (for example `language_model_core` → `language_model` → `language_models/provider/*`, plus `anthropic` and `open_ai` as raw API clients).

### How Tauri 2 ACL treats inline plugins (verified in source)

- **Every `plugin:` command is ACL-checked.** In `tauri/src/webview/mod.rs:1818-1823`, a plugin command is rejected unless a capability grants it. App (non-plugin) commands are only checked once an `AppManifest` exists.
- **Inline plugins can get ACL permissions without their own crate.** `tauri-build` has first-class support (`tauri-build/src/acl.rs:25-80`): `Attributes::new().plugin(name, InlinedPlugin::new().commands(&[..]).default_permission(DefaultPermissionRule::AllowAllCommands))`. This generates `allow-*`/`deny-*` permissions and a `<name>:default` set.
- **So inline plugins work.** Deino adds `"<name>:default"` to `capabilities/default.json` and lists the plugin in `build.rs`.
- **One specta builder per command group.** `tauri_specta::Builder::commands()` *overwrites* earlier calls (`refs/tauri-specta/src/builder.rs:176`), so you cannot compose one global builder from several modules. A per-feature plugin with its own `tauri_specta::Builder` and `.plugin_name()` is the natural modular unit (`refs/tauri-specta/examples/custom-plugin/plugin/src/lib.rs`).

### Recommendation for Deino (decisive)

Use three tiers. Don't use one crate per feature, and don't use anarlog-style plugin crates.

1. **Layer and infrastructure crates in `crates/`** (Tauri-free, unit-testable).
   - **Make a crate when** it has heavy native deps (STT, audio, llama), enforces an architectural boundary (`deino-net`; STT must not depend on it), or will be reused by DEV-02/03/04 (MCP server, REST API, CLI need the core without Tauri).
   - **Crate list:**
     - `deino-domain`: IDs, enums, DTOs, `AppError`.
     - `deino-db`: pool, migrations, `test_db()`.
     - `deino-core`: feature services and repos, as **modules**.
     - `deino-pipeline`
     - `deino-llm`
     - `deino-net`
     - `deino-secrets`
     - `deino-audio`
     - `deino-stt`
     - `deino-doc`: TipTap JSON to and from Markdown.
     - `deino-testkit`: dev-only.
   - **Keep it to about 11 crates, not 150.**
2. **Features are modules inside `deino-core`.** For example `crates/deino-core/src/meetings.rs` plus `meetings/{service.rs, repo.rs, model.rs, error.rs}`. Split a feature into its own crate only if it gains heavy deps or passes about 3k lines.
3. **IPC: one inline Tauri plugin per feature in the app crate.** For example `frontend/src-tauri/src/features/meetings.rs` plus `features/meetings/{commands.rs, events.rs}`, registered with `.plugin(features::meetings::init())`.
   - Each plugin owns its `tauri_specta::Builder` with `plugin_name("meetings")`. The generated TS calls `plugin:meetings|list`, so names are namespaced and short (`list`, `get`, `rename`) instead of `api_get_meetings`.

**Compile times.**
- Isolating `whisper-rs`, `ort`, cpal/Core Audio and llama behind `deino-stt` and `deino-audio` means they are rebuilt only when touched.
- Editing a service recompiles `deino-core` and the app crate only.
- Add `[profile.dev.package."*"] opt-level = 1` (dependencies optimised, app code fast to build), which both `refs/anarlog/Cargo.toml:1-8` and `refs/Cap/Cargo.toml:100-111` use.
- Hold off on cargo-hakari (`refs/Cap/crates/workspace-hack`) until clean builds exceed about 5 minutes.

**Testability.** Services in `deino-core` take `Arc<dyn Port>` dependencies and never see `tauri::*`, so `cargo test -p deino-core` runs with no webview or runtime.

**FND-02 command-registration pattern.** Inline plugin per feature plus an ACL manifest in `build.rs`.

```rust
// frontend/src-tauri/src/features/meetings.rs
//! IPC surface of the meetings feature: a thin Tauri plugin over `deino_core::meetings`.
mod commands;
mod events;

pub(crate) const NAME: &str = "meetings";

pub(crate) fn specta() -> tauri_specta::Builder<tauri::Wry> {
    tauri_specta::Builder::new()
        .plugin_name(NAME)
        .commands(tauri_specta::collect_commands![commands::list, commands::get, commands::rename])
        .events(tauri_specta::collect_events![events::MeetingChanged])
        .error_handling(tauri_specta::ErrorHandlingMode::Result)
}

pub(crate) fn init() -> tauri::plugin::TauriPlugin<tauri::Wry> {
    let builder = specta();
    tauri::plugin::Builder::new(NAME)
        .invoke_handler(builder.invoke_handler())
        .setup(move |app, _api| { builder.mount_events(app); Ok(()) })
        .build()
}
```

```rust
// frontend/src-tauri/src/features/manifest.rs  (included by build.rs AND by the app; append-only)
pub const FEATURES: &[(&str, &[&str])] = &[
    ("meetings", &["list", "get", "rename"]),
];
// build.rs
include!("src/features/manifest.rs");
fn main() {
    println!("cargo:rerun-if-changed=src/features/manifest.rs");
    let attrs = FEATURES.iter().fold(tauri_build::Attributes::new(), |attrs, (name, cmds)| {
        attrs.plugin(name, tauri_build::InlinedPlugin::new().commands(cmds)
            .default_permission(tauri_build::DefaultPermissionRule::AllowAllCommands))
    });
    tauri_build::try_build(attrs).expect("tauri build failed");
}
```

**Guard tests.** Write them in the anarlog style (`refs/anarlog/apps/desktop/src-tauri/src/lib.rs:752`, `main_capability_allows_cloudsync_lifecycle_commands`):
- **Capability test:** parse `capabilities/default.json` and assert that every `FEATURES` name has `"<name>:default"`.
- **Manifest drift test:** export each feature's bindings to a temp file, the way `refs/tauri-specta/tests/casing.rs:21` does, and assert that the set of `plugin:<name>|<cmd>` strings equals the manifest list.

Both rules then fail in CI, not at runtime.

**Legacy commands.** The about 190 legacy commands stay in the existing `generate_handler!` (moved to `src/legacy.rs`, with the `// ── CARD ──` banner rule) until a card ports them. Don't add an `AppManifest`, because that would put all legacy commands under the ACL.

### Copy vs reimplement

- **Reimplement** the plugin skeleton. It is about 20 lines, shown above; the source is `refs/tauri-specta/examples/custom-plugin/plugin/src/lib.rs` (MIT).
- **Copy the idea** of per-crate `AGENTS.md` with Owns, Does Not Own and Invariants (`refs/anarlog/crates/db-core/AGENTS.md`).
- **Don't copy** anarlog's per-plugin `package.json` and JS packaging, or spacedrive's daemon and `inventory` registry. `inventory` is clever but hides the registration list, and it relies on linker tricks.

## 2. Typed IPC (tauri-specta)

### Best found

- **Every Tauri reference uses tauri-specta.** None uses ts-rs.
- **Handy** (`refs/Handy/src-tauri/src/lib.rs:652-785`) uses `collect_commands!` and `collect_events!` (`HistoryUpdatePayload`, `StreamTextEvent`), and exports to `src/bindings.ts` in `#[cfg(debug_assertions)]` with `BigIntExportBehavior::Number`. Pins: `specta =2.0.0-rc.22`, `specta-typescript 0.0.9`, `tauri-specta =2.0.0-rc.21` (`refs/Handy/src-tauri/Cargo.toml:90-92`).
- **anarlog** uses the same pins (`refs/anarlog/Cargo.toml:347-349`).
  - Each plugin exports from a `#[test] fn export_types` into `plugins/<x>/js/bindings.gen.ts` (`refs/anarlog/plugins/settings/src/lib.rs`), and the app exports into `apps/desktop/src/types/tauri.gen.ts` (`refs/anarlog/apps/desktop/src-tauri/src/lib.rs:770`). Export from a **test** is deterministic and CI-friendly.
  - Generated files are excluded from lint and format (`refs/anarlog/.oxlintrc.json` `ignorePatterns: ["**/*.gen.ts"]`, `refs/anarlog/eslint.config.js`).
  - **Weakness:** commands return `Result<T, String>` (576 occurrences in `refs/anarlog/plugins`).
- **Cap** has the richest event typing: around 12 typed events, with enums such as `RecordingEvent` tagged `#[serde(tag = "variant")]` (`refs/Cap/apps/desktop/src-tauri/src/recording.rs:1192`, builder at `lib.rs:6762-6996`). It uses `ErrorHandlingMode::Throw`. Errors are stringly typed (678 occurrences of `Result<_, String>`).
- **tauri-specta itself** has the canonical recipes.
  - Typed `thiserror` + `Serialize` + `specta::Type` errors are at `refs/tauri-specta/examples/app/src-tauri/src/main.rs:81-120`.
  - Typed events with `Event` derive, `listen`, `emit` and `event_name` rename are at `main.rs:141-245`.
  - Typed `tauri::ipc::Channel<T>` (`with_channel` in `examples/tanstack-query/src-tauri/src/main.rs`).
  - Error modes are `Result` (default), `Throw` and `DataError` (`src/builder.rs`), and `typed_error_impl` lets you swap the runtime.
  - **New:** `crates/tauri-specta-query` generates TanStack Query `queries`, `mutations` and `queryKeys` (`refs/tauri-specta/crates/tauri-specta-query/src/lib.rs`). It is v0.0.1, so watch it but don't depend on it yet.

### Recommendation for Deino: setup recipe

1. **Dependencies.** Add these to `[workspace.dependencies]`: `specta = { version = "=2.0.0-rc.22", features = ["derive", "serde_json", "uuid", "chrono"] }`, `specta-typescript = "=0.0.9"`, `tauri-specta = { version = "=2.0.0-rc.21", features = ["derive", "typescript"] }`. This is the set proven in Handy and anarlog. Upgrade only as a set.
2. **Types.**
   - DTOs and IDs in `deino-domain` derive `serde::{Serialize, Deserialize}` + `specta::Type`, with `#[serde(rename_all = "camelCase")]`. A `common_derives!` macro as in `refs/anarlog/crates/template-app/src/lib.rs:24` keeps this to one line.
   - ID newtypes use `#[serde(transparent)]`.
3. **Commands** are annotated `#[tauri::command] #[specta::specta]`. They return `Result<T, AppError>` (see §3), take `State<'_, Arc<Service>>`, and are not generic over `Runtime`.
4. **Events:**
   - Broadcast state changes (`EntityChanged`, `PipelineProgress`, `SettingsChanged`, `RecordingStateChanged`) are `#[derive(tauri_specta::Event)]` types collected per plugin. Their names are plugin-namespaced automatically.
   - **Request-scoped streams** (LLM tokens for FND-09, import progress) use a typed `tauri::ipc::Channel<LlmStreamEvent>` argument instead of a global `llm-stream` event with `request_id` filtering. Channels are ordered, per-caller and need no listener cleanup.
5. **Export.**
   - One test, `frontend/src-tauri/src/bindings.rs::export_bindings`, iterates the features. It writes `frontend/src/lib/ipc/generated/<feature>.ts` using `BigIntExportBehavior::Number` and the prettier formatter, as anarlog does.
   - It then post-processes the output in about 10 lines. It **brands ID aliases**, rewriting `export type MeetingId = string` to `string & { readonly __brand: "MeetingId" }`. specta-typescript 0.0.9 has no branding, and every ID originates in Rust, so this is safe.
   - Ignore `src/lib/ipc/generated/**` in ESLint and Prettier.
   - Typed wrappers go in `frontend/src/features/<x>/api.ts` (plan §3.4 says `lib/ipc/<feature>.ts`; put them in the feature folder).
6. **CI freshness.** Run `cargo test -p deino-app bindings::export_bindings && git diff --exit-code frontend/src/lib/ipc/generated`. This is the same idea as `refs/plugins-workspace/.github/workflows/check-generated-files.yml`.
7. **Error mode.** Use `ErrorHandlingMode::Result`, so TS gets `{status:"ok",data}|{status:"error",error:AppError}`. Add a 10-line `unwrap(result)` in `lib/ipc/result.ts` that throws a typed `IpcError extends Error { code: ErrorCode }`. TanStack Query's `Register` augmentation then types `defaultError: IpcError`, and queries and mutations stay throw-based but fully typed.

### Copy vs reimplement

- **Copy** (MIT, with attribution):
  - the export-test pattern from `refs/anarlog/plugins/settings/src/lib.rs`;
  - the `common_derives!` macro;
  - the typed error and event examples from `refs/tauri-specta/examples/app`.
- **Reimplement** the branding post-process and `IpcError`.

## 3. Error handling

### Best found

- **No Tauri reference has typed IPC errors.** anarlog, Cap and Handy all collapse to `String` (anarlog's `impl Serialize for Error { serialize_str(self.to_string()) }`, `refs/anarlog/plugins/settings/src/error.rs`). Deino should be better than all of them.
- **Module error enums** use `thiserror` with `#[from]` sources (`refs/anarlog/plugins/db/src/error.rs`, `refs/plugins-workspace/plugins/store/src/error.rs` with `#[non_exhaustive]` and doc on every variant).
- **spacedrive** has a domain-categorised `ActionError` (`InvalidInput`, `PermissionDenied`, `Validation{field,message}`, `Timeout`, …) (`refs/spacedrive/core/src/infra/action/error.rs`).
- **zed** is the gold standard for error *content*. `LanguageModelCompletionError` has context-rich variants that keep `#[source]` and machine-usable fields such as `retry_after` and `category`, and it documents each variant's meaning (`refs/zed/crates/language_model_core/src/language_model_core.rs:192`).
- **zed `ResultExt`** has `log_err()`, `warn_on_err()`, `debug_assert_ok()` and `#[track_caller]` (`refs/zed/crates/gpui_util/src/lib.rs:225-260`). Its rule is "never `let _ =` a fallible call" (`refs/zed/.rules`).
- **Typed error enum with `specta::Type`** crossing IPC: `refs/tauri-specta/examples/app/src-tauri/src/main.rs:81-120` (`#[serde(skip)]` on non-serialisable sources).

### Recommendation for Deino

- **In `deino-domain/src/error.rs`:**

```rust
#[derive(Debug, Clone, Copy, Serialize, specta::Type, PartialEq, Eq)]
#[serde(rename_all = "snake_case")]
pub enum ErrorCode { NotFound, Invalid, Conflict, Unavailable, PermissionDenied, Network, Llm, Cancelled, Internal }

/// The only error type that crosses IPC. `message` is user-safe English; details go to the log.
#[derive(Debug, Clone, Serialize, specta::Type, thiserror::Error)]
#[error("{code:?}: {message}")]
pub struct AppError { pub code: ErrorCode, pub message: String }

pub trait ErrorClass { fn code(&self) -> ErrorCode; }   // implemented by every module error
impl<E: ErrorClass + std::fmt::Display> From<E> for AppError { /* code + to_string() */ }
```

- **Module errors.** Each module has `error.rs` with a `thiserror` enum. Variants carry context fields and `#[source]`, as zed does, and the enum implements `ErrorClass`. Add `fn is_retryable(&self) -> bool` where the pipeline or LLM layers need it (zed's `retry_after` idea).
- **Command boundary.** The command layer is the only place that logs the full error chain (`log::warn!(target: "ipc", "{err:#}")`, with IDs only) and then returns `AppError`.
- **`anyhow`** is allowed only in `main`, `build.rs`, xtask and eval harnesses. The plan's `PipelineStage::run -> anyhow::Result` should become `Result<StageOutcome, StageError>`, so retries can be classified.
- **Copy zed's `ResultExt` idea** as about 30 lines in `deino-domain/src/result_ext.rs` (`log_err`, `warn_on_err`), plus a clippy rule: `let_underscore_must_use = "deny"`.

### Copy vs reimplement

- **Reimplement** the error types above. Zed is GPL. The design is small and specific to Deino.
- **Copy** the `#[serde(skip)]` pattern for sources from tauri-specta (MIT).

## 4. State and dependency injection

### Best found

- **anarlog: composition in `main()`.** `refs/anarlog/apps/desktop/src-tauri/src/lib.rs` opens the DB, builds the supervisor, chooses `ActualAudio` or `MockAudio` (`:92`), then chains `.plugin(..)` calls (`:259-393`). Plugins expose `XxxPluginExt` traits on `Manager` (`refs/anarlog/plugins/settings/src/ext.rs`), which is ergonomic but service-locator style.
- **anarlog interface crates** are trait-only crates that implementations depend on (`refs/anarlog/crates/calendar-interface`, used by `crates/calendar` and `plugins/calendar`).
- **spacedrive** passes an `Arc<CoreContext>` into every operation (`refs/spacedrive/core/src/cqrs.rs`, `core/src/context.rs`). That is a context object rather than narrow ports.
- **zed:**
  - **Small traits with one required method plus provided defaults.** `HttpClient::send` is required, and get/post are defaults (`refs/zed/crates/http_client/src/http_client.rs:122`). `LanguageModel::stream_completion` is required, and `stream_completion_text` and `stream_completion_tool` are defaults (`refs/zed/crates/language_model/src/language_model.rs:383-470`).
  - **Fakes ship with the trait** behind a `test-support` feature: `FakeFs` (`crates/fs/src/fs.rs:1444`), `FakeHttpClient` (`crates/http_client/src/http_client.rs:437`) and `FakeLanguageModelProvider` (`crates/language_model/src/fake_provider.rs:18`).

### Recommendation for Deino

- **Composition root** in `frontend/src-tauri/src/composition.rs` (the plan's `app_state.rs`, under a clearer name).
  - `pub struct Services { meetings: Arc<MeetingService>, settings: Arc<SettingsService>, llm: Arc<Gateway>, … }`.
  - `fn build(paths, config) -> Result<Services>` wires concrete adapters (`SqliteMeetingRepo`, `KeychainSecretStore`, `SystemClock`, `ReqwestNet`) into services.
  - `lib.rs` calls `app.manage(services.meetings.clone())` for each service. Commands take `State<'_, Arc<MeetingService>>`, never a god-`AppState`.
- **Ports** live next to their consumer (`deino-core/src/ports.rs`). Examples: `Clock`, `MeetingStore` split into `MeetingReader` and `MeetingWriter` (interface segregation, §3A), `EventSink`, `SecretStore`, `LlmGateway`, `CalendarSource`.
  - Object-safe ports are used as `Arc<dyn Port>` with `#[async_trait]` for readability.
  - Generics only on hot paths (audio frames).
- **`EventSink` port.** Core services emit `DomainEvent` values. The app's `TauriEventSink` maps them to typed specta events. That keeps `deino-core` Tauri-free, so DEV-02/03 can reuse it with an SSE sink.
- **Fakes** live in the crate that owns the trait, behind `features = ["test-support"]` (the zed pattern). `deino-testkit` re-exports them together with fixtures. Prefer hand-written fakes over `mockall`.
- **No `once_cell` or global statics in new code.** Deino today has `static RECORDING_FLAG`, and anarlog also uses statics (`EXIT_FLUSH_COMPLETE`). Treat both as legacy to remove.

### Copy vs reimplement

- **Reimplement** all of this. It is Deino-specific wiring.
- **Borrow** zed's "one required method plus defaults" trait shape, as a pattern only.

## 5. Database

### Best found

- **anarlog** uses sqlx (`=0.9.0-alpha.1`, `refs/anarlog/Cargo.toml:399`) with **runtime** queries. There are no `query!` or `query_as!` macros (0 hits) and about 1,450 `sqlx::query*` call sites, for example `refs/anarlog/crates/db-app/src/template_ops.rs`.
  - **Safety comes from tests instead.** `refs/anarlog/crates/db-app/src/schema_tests/*.rs` runs every helper against an in-memory DB with all migrations applied.
  - **`test_db()`:** `DbStorage::Memory`, `max_connections: Some(1)` (an in-memory SQLite is per-connection), `foreign_keys: true`, then `prepare_schema` (`refs/anarlog/crates/db-app/src/schema_tests/mod.rs:45-60`).
  - **Migrations are an append-only manifest** of `include_str!` SQL steps (`refs/anarlog/crates/db-app/src/lib.rs:74`). There are 89 files named `YYYYMMDDHHMMSS_desc.sql`, all tables are `STRICT`, and `CHECK` constraints validate enums, trimming and JSON shape.
  - **Migration round-trip tests** use `migration_steps_before(id)`: apply the old steps, insert legacy rows, apply the rest, then assert (`schema_tests/mod.rs:70-77`, `schema_tests/migrations.rs`).
  - **Reactivity.** `db-change` installs SQLite `update_hook`, `commit_hook` and `rollback_hook` in `SqlitePoolOptions::after_connect` and emits `table + seq` after commit (`refs/anarlog/crates/db-change/src/notifier.rs:61-90`, `crates/db-change/AGENTS.md`). `db-reactive` re-runs live queries using `EXPLAIN QUERY PLAN` dependency analysis (`crates/db-reactive/src/explain.rs`).
  - **Local storage and sync:**
    - SQLite through sqlx, opened by `db-core` (WAL, busy timeout 5 s, `refs/anarlog/crates/db-core/src/lib.rs`).
    - Sync is done by **SQLite Sync / "CloudSync"**, a vendored CRDT SQLite extension from sqlite.ai (`refs/anarlog/crates/cloudsync`, with `AGENTS.md` pointing to sqlite-sync 1.2.0). It adds E2EE (`crates/e2ee`, `db-app/src/e2ee.rs`).
    - The frontend talks SQL through **Drizzle sqlite-proxy** over `plugins/db` (`refs/anarlog/packages/db/AGENTS.md`, `packages/db-react/src/index.ts` live queries).
    - TinyBase is legacy. A custom lint `anlg/no-raw-tinybase` is set to error (`refs/anarlog/.oxlintrc.json`).
    - A markdown "vault" folder is kept in sync by `plugins/fs-sync`.
- **Handy** uses `rusqlite` + `rusqlite_migration` with inline `M::up(..)` (`refs/Handy/src-tauri/src/managers/history.rs:5-33`). Fine for one table, not for Deino.
- **spacedrive** uses SeaORM + sea-orm-migration (`refs/spacedrive/core/Cargo.toml:36-44`). It is heavier, and its ORM entities would fight the plan's `query_as!` rule.
- **Compile-checked queries** (`query_as!` + committed `.sqlx`) are used by **none** of the references.

### Recommendation for Deino

- **Keep sqlx 0.8 with `sqlx::migrate!`.** Keep the plan's compile-checked `query_as!`, scoped so it doesn't hurt:
  - All SQL lives in `deino-db` (pool and migrations) and in `deino-core/**/repo.rs`.
  - Commit `.sqlx/` at the workspace root (`cargo sqlx prepare --workspace`).
  - Set `SQLX_OFFLINE=true` in `.cargo/config.toml` `[env]`, so builds and agent worktrees never need a live DB.
  - CI runs `cargo sqlx prepare --workspace --check`.
  - Enum columns use `as "status: MeetingStatus"` overrides, with `#[derive(sqlx::Type)] #[sqlx(rename_all = "snake_case")]`.
- **Schema rules adapted from anarlog:**
  - `STRICT` on every new table, plus `CHECK` constraints for enums (the plan already asks for this).
  - Unlike anarlog, use real FKs with `ON DELETE`, because Deino does not sync.
  - `NOT NULL` with defaults.
  - Use TEXT UUIDv7 (`uuid` with `v7`).
- **`deino-db::test_db()`:** a `sqlite::memory:` pool with **`max_connections(1)`**, otherwise each connection sees an empty DB. It applies `foreign_keys=ON`, runs `MIGRATOR.run`, and an optional `seed_fixtures(&pool)`.
- **Migration round-trip test (FND-07).** Build a `Migrator` holding the migrations `< version` (the public `migrations: Cow<[Migration]>` field), seed rows in the old format, run the full migrator, then assert. This is anarlog's `migration_steps_before` idea.
- **Pool.** WAL, one writer pool (`max_connections(1)`) and a read pool (4), both with `busy_timeout 5s`. Install anarlog-style commit hooks on the **writer** in `after_connect`, using `LockedSqliteHandle::set_update_hook` and `set_commit_hook`, which exist in sqlx 0.8.6 (`sqlx-sqlite-0.8.6/src/connection/mod.rs:427,486`). Emit a typed `DbChanged { tables: Vec<Table>, seq }` event.
  - The frontend maps `Table` to query-key prefixes and invalidates them, so TanStack Query freshness is automatic and cannot be forgotten. That is the FND-13 "invalidate on Rust events" helper.
- **Repository pattern.**
  - One `repo.rs` per aggregate.
  - One function per query.
  - Writes take `&mut SqliteConnection` or `&mut Transaction` so services compose transactions.
  - Reads take `&SqlitePool`.
  - Hot list queries get an `EXPLAIN QUERY PLAN` test asserting `USING INDEX`.
- **Don't adopt:** frontend SQL (Drizzle proxy), live-query `db-reactive`, CloudSync or SeaORM. All of them conflict with Rust-owned services and FND-12 egress rules.

### Copy vs reimplement

- **Copy and adapt** (MIT, with attribution):
  - `db-change/src/notifier.rs`, about 100 lines, as `deino-db/src/change_notifier.rs`;
  - the `test_db()` shape;
  - the migration round-trip technique.
- **Reimplement** repos with `query_as!`.

- **Grammar and local model.** `refs/anarlog/crates/gbnf` is only 99 lines of fixed grammars, which is minor. `crates/local-llm-core` contains LM Studio and model management.
- **Handy** has an OpenAI-compatible client with `response_format: json_schema` that **retries without the schema when the upstream returns 400 or 422** (`refs/Handy/src-tauri/src/llm_client.rs:320-390`). Its tests use a local `TcpListener` fake server (`:590`).
- **zed, the gold standard for the abstraction (pattern only):**
  - **Three layers.**
    - Raw API crates with wire types: `crates/anthropic`, `crates/open_ai` (`completion.rs`, `responses.rs`).
    - Provider adapters: `crates/language_models/src/provider/{anthropic,open_ai,ollama,llama_cpp,open_router,…}.rs`.
    - A UI-free core with the request model, event stream, errors, tool schema and rate limiter: `crates/language_model_core/src/*.rs`.
  - **Event enum.** `LanguageModelCompletionEvent` has the variants `Queued`, `Started`, `Text`, `Thinking`, `ToolUse`, `ToolUseJsonParseError`, `Stop(StopReason)` and `UsageUpdate` (`language_model_core.rs:42`).
  - **Tool schemas.** They are generated with schemars draft-07, with subschemas inlined and `$ref` and `$defs` removed for provider compatibility (`refs/zed/crates/language_model_core/src/tool_schema.rs`).
  - **`RateLimiter`** in `rate_limiter.rs`.
  - **`FakeLanguageModelProvider`** for tests.

### Recommendation for Deino (`crates/deino-llm`)

**Module layout (each file ≤300 lines):**
- `gateway.rs`: the `Gateway` holds `RouteTable` and `Providers`. It provides `complete`, `stream`, `structured::<T>` and `run_tools`, and writes `llm_calls`.
- `route.rs`: `enum Route { NotesEnhance, Chat, ExtractActionItems, … }`. Routes are an enum, not strings, and implement `specta::Type` for the Settings → AI table.
- `provider.rs`:
  - `#[async_trait] trait LlmProvider { fn id(&self) -> ProviderId; async fn stream(&self, req: CompletionRequest) -> Result<EventStream, LlmError>; }`.
  - `complete()` is a provided default that collects the stream, following zed's one-required-method shape.
- `event.rs`: `enum CompletionEvent { Text(String), ToolUse(ToolCall), Usage(Usage), Stop(StopReason) }`.
- `providers/anthropic/{client.rs, wire.rs}`, `providers/openai_compat/{client.rs, wire.rs}` (covers OpenAI, Groq, OpenRouter and custom endpoints), `providers/ollama.rs` and `providers/builtin.rs` (the llama-helper sidecar over stdout JSON lines).
- `sse.rs`: one SSE line parser shared by all HTTP providers. Use the `eventsource-stream` crate (MIT/Apache) or about 60 lines of your own code.
- `structured.rs`:
  - The schema comes from `schemars` 1.x draft-07 with inlined subschemas (zed technique).
  - Anthropic uses the tool trick; OpenAI uses `response_format json_schema`. If a 400 or 422 comes back, fall back to prompt-only output (the Handy technique).
  - Validate with `serde_json::from_str::<T>`. Make one repair retry that feeds the parse error back.
- `tools.rs`: the tool loop with a max-turns constant and a `ToolRegistry` trait object.
- `prompts/`: **askama** templates `*.md.jinja` with typed structs, one per route.
- `user_templates.rs`: **minijinja** with strict undefined and a variable allowlist, for NOT-04 user templates.
- `mock.rs` (feature `test-support`): `MockProvider` keyed by `Route`, returning scripted `CompletionEvent` sequences, including tool calls.
- `error.rs`: `LlmError` has the variants `NoKey{provider}`, `Auth`, `RateLimited{retry_after}`, `ContextTooLong`, `Provider{status, code, message}`, `Network(#[source])`, `Parse` and `Cancelled`. It implements `is_retryable()`.

**Rules:**
- **HTTP.** Providers get a `deino_net::ScopedClient` for their own `ServiceId` (§1 FND-12). They never get `reqwest`.
- **Streaming to the UI** goes through `tauri::ipc::Channel<LlmStreamEvent>` (see §2).
- **Testing.**
  - Prompt snapshots use `insta` inline snapshots through a `tpl_snapshot!`-style macro.
  - Gateway and tool-loop tests run against `MockProvider`.
  - Per-provider wire tests feed recorded SSE fixtures (`tests/fixtures/anthropic_stream.txt`) to the parser. There is no network in CI.
- **Evals.** Use `crates/deino-llm/tests/llm_eval/main.rs` with `harness = false`. Cases are fixtures plus expectations (`ContainsFact`, `NotContains`, `MarkdownHasHeading`, `ValidJsonAgainst<T>`). Run it as `DEINO_EVAL=1 cargo test -p deino-llm --test llm_eval -- notes_enhance`, aliased as `pnpm eval notes.enhance`. It is never part of CI.
- **Dates.** Use a `Clock` port instead of anarlog's global `set_current_date_override`.

## 7. Frontend architecture

### Best found

- **Routing and build.** All five Tauri references use **Vite**, and none uses Next.js.
  - anarlog uses `@tanstack/react-router` with file-based routes and `autoCodeSplitting` (`refs/anarlog/apps/desktop/vite.config.ts`, `src/routes/__root.tsx`, `src/routes/app/note.$sessionId.tsx`, generated `src/routeTree.gen.ts`).
  - Handy is Vite with a hand-rolled router. spacedrive uses Vite with react-router 6. Cap uses Vite with SolidStart.
- **State.**
  - anarlog: TanStack Query for Rust data (`@tanstack/react-query`, per-feature `queries.ts`, e.g. `src/contacts/queries.ts`), **Zustand** for UI and workflow state (`src/store/zustand/{listener,ai-task,tabs}`) and TanStack Form for forms.
  - anarlog's `no-use-effect` rule says to derive state, use query or mutation, use event handlers or `useMountEffect`, and never call raw `useEffect` (`refs/anarlog/.agents/skills/no-use-effect/SKILL.md`).
  - Handy also uses Zustand.
- **Component structure.**
  - anarlog uses feature folders with colocated tests and kebab-case files (`src/contacts/{person-item.tsx, queries.ts, queries.test.tsx}`). The median file is 96 lines and p90 is 460.
  - A shared `packages/ui` (shadcn on Radix) and one icon set are enforced by ESLint `no-restricted-imports` (`refs/anarlog/eslint.config.js`).
- **Design tokens.** `refs/anarlog/packages/design-system/src/tokens.css` (`:root` and `.dark` HSL triplets, shadcn names, warm-neutral greys, which is very close to Deino's §3B), with Tailwind v4.
- **Editor.**
  - anarlog left TipTap for raw ProseMirror (`@handlewithcare/react-prosemirror`, `packages/editor`). It still **stores TipTap-dialect ProseMirror JSON** and has a Rust crate for **TipTap JSON ↔ Markdown ↔ mdast**, with validation and merge (`refs/anarlog/crates/tiptap/src/{lib.rs,from_md.rs,to_ast.rs,validate.rs,merge.rs}`, insta-tested).
  - Deino uses BlockNote 0.36, whose block JSON can only be produced in JS.

### Recommendation for Deino

1. **Move from Next.js static export to Vite + TanStack Router (file-based) + TanStack Query.** The cost is clearly worth it:
   - Next's SSR, RSC, Image and route-handler features are all dead under `output: 'export'`. Static export forbids dynamic segments without `generateStaticParams`, which is why Deino has `/meeting-details?id=`.
   - TanStack Router gives typed `$meetingId` params, **zod-validated typed search params** (filters, tabs and `?t=` playback offsets for TRN-03 and ORG-07), and loaders that call `queryClient.ensureQueryData(meetingQuery(id))`.
   - It removes the webpack ProseMirror alias hack in `deino/frontend/next.config.js`.
   - **Vitest** shares the Vite config and aliases.
   - `pnpm dev:mock` becomes a Vite mode with an alias swap (see §9).
   - It matches every reference app, so agents can copy patterns directly.
   - **Migration cost:** the 171 files are client components already. The work is the router shell, about 6 routes, and `next/link` → `Link`, and it fits inside FND-10, which already replaces `layout.tsx` and the Sidebar. Run it as **FND-10a** before the rest of FND-10.
2. **State.**
   - Rust data uses TanStack Query only. Query keys are built from generated per-feature key factories in `features/<x>/queries.ts`. Mutations invalidate by key, and `DbChanged` events auto-invalidate by table (see §5).
   - UI state is local, or held in small Zustand stores per feature.
   - The React Context providers in `contexts/` go away. TranscriptContext becomes a query plus a typed event subscription.
   - Adopt anarlog's no-`useEffect` rule, with a `useMountEffect` helper.
3. **Structure.** Keep plan §3A: `features/<x>/{components/, hooks/, api.ts, queries.ts, copy.ts, types.ts}`, with kebab-case files and tests colocated as `*.test.tsx`. Routes in `src/routes/` stay thin: they only compose feature components.
4. **Design tokens.**
   - Use Tailwind v4 with `@tailwindcss/vite`.
   - `src/styles/tokens.css` defines the §3B semantic tokens (`--bg`, `--fg-muted`, `--accent`, …) for `:root` and `[data-theme=dark]`, plus `@theme inline` mapping them to utilities.
   - shadcn primitives live in `src/ui/`.
   - Ban raw colour utilities (`text-gray-500`, hex) with an ESLint `no-restricted-syntax` regex on `className`.
5. **Editor: move from BlockNote to TipTap 3** (MIT core, headless) when NOT-01 builds the notepad. Freeze BlockNote until then.
   - **The decisive reason:** the NOT-02 pipeline stage runs in **Rust**. It needs to turn LLM Markdown into the stored document JSON, attach provenance and citations as marks or nodes, and convert back to Markdown for export, MCP and LLM context. anarlog's `crates/tiptap` does exactly this for TipTap JSON. BlockNote JSON can only be produced in JS.
   - A Granola-style calm document also fits plain ProseMirror better than BlockNote's block handles.

### Copy vs reimplement

- **Copy** (MIT, with attribution):
  - `crates/tiptap` into `crates/deino-doc`;
  - the `tokens.css` structure;
  - the `test-setup.ts` Tauri shim (`refs/anarlog/apps/desktop/src/test-setup.ts`);
  - the `no-use-effect` skill text into Deino's `CLAUDE.md`.
- **Reimplement** routes and features.

## 11. Zed: what makes its Rust idiomatic (reference only)

**Observations.**
- **Small single-purpose crates.** There are 249, and lib roots are named after the crate (`[lib] path = "src/git_ui.rs"`, `refs/zed/crates/git_ui/Cargo.toml:11-14`).
- **No `mod.rs`.** There are 6 in about 1,900 files.
- **Error context everywhere.** There are 2,709 `.context()` calls and 813 `bail!`/`ensure!` calls.
- **`ResultExt`** helpers (above).
- **Fakes behind `test-support` features.**
- **Executors and timers are deterministic in tests** (clippy bans `smol::Timer::after`).
- **gpui separates concerns.** `Entity<T>` owns state; `Render`/`RenderOnce` produce views; Actions are user intents; `cx.notify()` and `EventEmitter` handle change propagation; `Task`s are cancelled on drop unless stored or `detach_and_log_err` is called (`refs/zed/.rules`, GPUI section).

**What not to copy.**
- **File size.** zed's median file is about 309 lines and p90 about 1,900, which breaks Deino's 300-line cap.
- **`style = "allow"`.**

**Rules Deino should adopt:**

1. **Propagate with `?` and add context.** Use `.context("loading meeting {id}")` at the edges and context fields in `thiserror` variants inside the core. Never discard a `Result` with `let _ =`. If ignoring is intended, use `.log_err()` or `.warn_on_err()` from a tiny `ResultExt`.
2. **No panicking APIs in non-test code.** That means no `unwrap`, `expect` or `panic!`, and no unchecked indexing (`slice[i]` → `.get(i)`). Enforce it with clippy `unwrap_used`, `expect_used`, `indexing_slicing` (warn) and `panic`.
3. **Full-word names.** `queue`, not `q`; `meeting_id`, not `mid`. The only abbreviations are id, url, db, llm, ui, ms.
4. **No new `mod.rs`.** Use `src/meetings.rs` + `src/meetings/service.rs`, so editor tabs and stack traces name the module. (This changes plan §3.3's `mod.rs`; existing files stay until touched.)
5. **Name each crate's lib root after the crate** (`[lib] path = "src/deino_llm.rs"`). Crate names are `deino-<noun>`.
6. **Comments explain *why* only.** No section-banner comments that narrate the code, and no commented-out code.
7. **Traits have one required method and many provided defaults.** For example `LlmProvider::stream` → `complete`, and `NetClient::send` → `get_json` / `post_json`. Small surfaces are easy to fake and honour Liskov substitution.
8. **The fake lives with the trait,** behind `features = ["test-support"]` (`FakeClock`, `MockProvider`, `InMemorySecretStore`). Tests depend on `crate = { features = ["test-support"] }`. No mocking frameworks.
9. **Error enums are documented data, not strings.** Each variant has a `///` doc saying when it happens, carries the fields a caller needs to decide what to do (`retry_after`, `status`, `provider`) and keeps `#[source]`.
10. **Encode architecture in `clippy.toml` `disallowed-*` entries** with `reason` and `replacement`: `reqwest::Client`, `tokio::spawn`, `Utc::now`, `std::thread::sleep`.
11. **Layer integrations three ways:**
    - a wire-types API client module (`providers/anthropic/wire.rs`);
    - an adapter that implements the core trait (`providers/anthropic/client.rs`);
    - a core crate with no I/O knowledge (`deino-llm/src/provider.rs`).
12. **Tests are deterministic.** Inject `Clock` and drive time manually. Never `sleep` in tests. Use property or randomized tests (`proptest`) for parsers and merges: SSE, TipTap ↔ Markdown, transcript segment merging.
13. **Never fire and forget.** Every spawned task is stored (a `JoinHandle` in the owner, so dropping the owner cancels it), tracked (`tokio_util::task::TaskTracker` + `CancellationToken`), or explicitly detached with a logged error.
14. **Shadow clones into async blocks:** `tokio::spawn({ let repo = repo.clone(); async move { … } })`. That keeps the clone's scope visible and minimal.
15. **One lint entry point for local and CI** (`scripts/clippy.sh` = clippy `--workspace --all-targets -D warnings`, then `cargo shear`, `typos`). Big test suites live in sibling `<module>_tests.rs` files.
16. **State vs view, in gpui terms.** Rust services own state and emit change events. React renders and sends intents (commands); it never owns a copy of server state outside TanStack Query.

## (b) Recommendations by card

### FND-02 · Dead code, English-only, modular commands
- **Adopt inline Tauri plugins per feature.**
  - The ACL works through `tauri_build::InlinedPlugin` + `DefaultPermissionRule::AllowAllCommands` (`tauri-build/src/acl.rs:25-80`), and plugin commands are always ACL-checked (`tauri/src/webview/mod.rs:1818-1823`).
  - Use one `tauri_specta::Builder` per plugin, because `commands()` overwrites (`refs/tauri-specta/src/builder.rs:176`).
- **Append-only manifest.** `src/features/manifest.rs` is `include!`d by `build.rs`. Each feature adds one line to the manifest, one `.plugin(…)` call and one `"<name>:default"` capability entry.
- **Move capabilities** out of `tauri.conf.json` into `capabilities/default.json`. Add a test asserting every manifest feature is granted (`refs/anarlog/apps/desktop/src-tauri/src/lib.rs:752`).
- **Move legacy commands** to `src/legacy/` under the existing `generate_handler!`. Don't add an `AppManifest`, which would ACL-gate every legacy command.
- **Document in `CLAUDE.md`** with the 15-line example from §1. Name it "Command registration: inline plugin". Write ADR 0002.
- **Remove `whatlang`, the language UI and the `summary/language_detection.rs` stack.** Hard-code `en` as a `const TRANSCRIPTION_LANGUAGE: &str = "en"` with a doc comment.

### FND-03 · CI and quality gates
- **One `ci.yml`** with path filters and `concurrency: cancel-in-progress` (`refs/anarlog/.github/workflows/lint.yaml`, `refs/Handy/.github/workflows/test.yml`).
- **macOS job:** fmt check, `scripts/clippy.sh` (`-D warnings`, the shape of `refs/zed/script/clippy`) and `cargo nextest run --workspace`.
- **Linux job:** `cargo check --workspace`.
- **Rust cache:** read `rust-toolchain.toml` into `dtolnay/rust-toolchain`, then `Swatinem/rust-cache@v2` (`refs/anarlog/.github/actions/rust_install/action.yaml`). No sccache.
- **Frontend job:** `pnpm install --frozen-lockfile`, `typecheck`, `lint`, `vitest run`, `vite build` (`refs/anarlog/.github/workflows/desktop_ci.yaml` js_ci).
- **Release:** delete the upstream S3/Zackriya workflows. Add a manual `release-macos.yml` using `tauri-apps/tauri-action` (unsigned DMG artifact).
- **Branch protection** requires `rust`, `frontend`, `bindings` and `pr-title`.

### FND-04 · Fixtures and mocked-IPC dev mode
- **`deino_db::test_db()`:** `sqlite::memory:` with `max_connections(1)` and FKs on, running `MIGRATOR`; plus `seed_fixtures(&pool)` (`refs/anarlog/crates/db-app/src/schema_tests/mod.rs:45-60`).
- **Fixture loader** in `deino-testkit` reads `fixtures/meetings/*.json` into typed `deino-domain` DTOs. Parsing is the schema check.
- **`pnpm dev:mock` = `vite --mode mock`.** `resolve.alias` swaps `@/lib/ipc/generated/*` → `@/dev/mock-ipc/*`, and each mock module `satisfies typeof generated.commands`, so stale mocks fail typecheck. This beats string-keyed `mockIPC`.
- **Vitest setup** reuses the same alias, plus the `__TAURI_INTERNALS__` shim from `refs/anarlog/apps/desktop/src/test-setup.ts` for event APIs.
- **Mock audio:** `MockAudioSource` (feature `test-support`) plays fixture `mic`/`system` tracks, selected in `composition.rs` by `DEINO_MOCK_AUDIO` in debug builds (`refs/anarlog/crates/audio-mock/src/lib.rs`, `apps/desktop/src-tauri/src/lib.rs:92`).
- **`dev_seed_fixtures`** goes in a `#[cfg(debug_assertions)]` dev feature plugin, so it is absent from the release manifest.

### FND-06 · Typed settings and Keychain secrets
- **Settings struct.** `Settings` in `deino-core/src/settings/model.rs`:
  - `#[serde(default)]` on every section, `version: u32`, and `specta::Type`;
  - sections are sub-structs (`AudioSettings`, `AiSettings`, `PrivacySettings`), so each file stays ≤300 lines (unlike `refs/Handy/src-tauri/src/settings.rs`, which is 1,792 lines).
- **Persistence.** `SettingsStore` writes atomically (temp file, `fsync`, rename).
- **`settings_patch`** accepts an RFC 7396 merge-patch `serde_json::Value` **only at the command edge**. It merges, then deserialises into `Settings` and validates, so a bad patch is rejected as `ErrorCode::Invalid`.
- **Events.** Emit a typed `SettingsChanged` event. `useSettings()` is a TanStack Query hook invalidated by it.
- **Secrets.** `deino-secrets` defines `trait SecretStore { set, has, delete, get(pub(crate) for Rust consumers only) }` with `KeychainSecretStore` (keyring, service `com.xenshreyas.deino`) and `InMemorySecretStore`. The `SecretSlot` trait idea comes from `refs/anarlog/plugins/store2/src/chunked.rs`.
- **Unsigned or ad-hoc-signed builds** can lose Keychain ACL access when the binary signature changes. anarlog ships `repair_macos_keychain_access` (`refs/anarlog/plugins/store2/src/commands.rs:93`). Plan a "re-enter keys" UX for this.
- **Migration tests:** old SQLite `settings` rows plus the tauri-store JSON go into `Settings` and the Keychain. Assert that no key remains in SQLite or JSON afterwards.

### FND-07 · Core schema
- **One migration file.** All tables are `STRICT` with `CHECK` enum constraints (anarlog's `refs/anarlog/crates/db-app/migrations/20260710223922_canonical_data_model.sql` has 18 `STRICT` tables). Add real FKs with `ON DELETE`, which anarlog omits only because of sync.
- **Enums** are `#[derive(sqlx::Type, specta::Type)]` in `deino-domain`. Queries use `query_as!` with `as "status: MeetingStatus"` overrides. `.sqlx/` is committed and `SQLX_OFFLINE=true`.
- **Round-trip test:** a `Migrator` holding the migrations before the FND-07 version, seed old `transcripts` rows, run all migrations, then assert the `transcript_segments` rows with `channel='mixed'` (anarlog `migration_steps_before`, `schema_tests/mod.rs:70-77`).
- **One `repo.rs` per aggregate** in `deino-core/src/<feature>/`. Writes take `&mut SqliteConnection` so services own transactions. Each list query has an `EXPLAIN QUERY PLAN` test asserting index use.
- **Writer hooks.** Install `set_update_hook` and `set_commit_hook` on the writer pool through `after_connect` (sqlx 0.8.6 supports them). This emits `DbChanged{tables, seq}` for automatic query invalidation (`refs/anarlog/crates/db-change/src/notifier.rs`, `AGENTS.md` rules: emit only after commit, clear on rollback).
- **Newtype IDs** wrap UUIDv7 (`MeetingId(Uuid)`) with `#[serde(transparent)]` and `sqlx::Type` `transparent`.

### FND-08 · Pipeline job runner
- **Model on spacedrive's job contract** (`refs/spacedrive/core/src/infra/job/traits.rs`: `NAME`, `RESUMABLE`, `VERSION` consts and `on_pause`/`on_resume`/`on_cancel` hooks; `refs/spacedrive/docs/core/jobs.mdx`: a lifecycle table and **startup reconciliation**, so no zombie `running` rows).
- **Stage trait:** `#[async_trait] trait PipelineStage: Send + Sync { fn id(&self) -> StageId; fn order(&self) -> u16; async fn run(&self, ctx: &StageCtx, meeting: MeetingId) -> Result<StageOutcome, StageError>; }`. Use methods, not associated consts, so the trait stays object-safe for `Arc<dyn PipelineStage>`.
  - `StageError` implements `is_retryable()`.
  - `StageCtx` carries the ports, a `CancellationToken` and an `EventSink`.
- **Registry** is `registry.rs` returning `Vec<Arc<dyn PipelineStage>>` sorted by order. Adding a stage is one line.
- **Concurrency:** a global `Semaphore(2)` plus a per-meeting `Mutex` map. Backoff is computed from the injected `Clock`, and tasks are tracked with `TaskTracker`. No raw `tokio::spawn`; this is enforced by clippy `disallowed-methods`.
- **`PipelineProgress`** is a typed specta event. The UI strip subscribes and invalidates `pipeline_status`.
- **Tests:** fake stages that succeed, fail twice, or hang until cancelled; `FakeClock`; a "restart" means a new `Runner` on the same `test_db()`.

### FND-09 · LLM gateway
- **Three layers** (zed pattern, reimplemented): wire types per provider, an adapter that implements `LlmProvider`, and a provider-agnostic core (`refs/zed/crates/language_model_core/src/language_model_core.rs:42,192`, `crates/language_models/src/provider/`).
- **`LlmProvider` has one required method,** `stream()`. `complete()` is a provided default. The `CompletionEvent` enum is `Text | ToolUse | Usage | Stop`. The `LlmError` taxonomy carries `retry_after`.
- **Structured output:** schemars draft-07 with subschemas inlined (`refs/zed/crates/language_model_core/src/tool_schema.rs`). Anthropic uses the tool trick; OpenAI uses `json_schema` with a fallback on 400/422 (`refs/Handy/src-tauri/src/llm_client.rs:320-390`). Make one repair retry with the parse error.
- **Prompts:**
  - built-in prompts are **askama** `.md.jinja` templates with insta inline snapshots (`refs/anarlog/crates/template-app/src/title.rs`, `crates/askama-utils/src/lib.rs`);

- **Streaming to the UI** uses a typed `tauri::ipc::Channel<LlmStreamEvent>` per request, not a global event (`refs/tauri-specta/examples/tanstack-query/src-tauri/src/main.rs` `with_channel`).
- **`MockProvider`** sits behind `test-support` and is keyed by `Route`. The tool-loop tests script tool calls.
- **Evals:** `tests/llm_eval/main.rs` with `harness = false` (libtest-mimic) and an `Expectation` enum (`refs/anarlog/crates/template-app/Cargo.toml:18-21`, `crates/template-eval/src/eval/expectations.rs`). `pnpm eval <route>` runs it with `DEINO_EVAL=1`.

### FND-12 · Network client and data-egress controls
- **`deino-net` is the only crate that depends on `reqwest`.**
  - Trait `NetClient` has one required `send(Request) -> Response`, with JSON helpers as defaults (the zed `HttpClient` shape, `refs/zed/crates/http_client/src/http_client.rs:122`).
  - `FakeNetClient` sits behind `test-support`.
- **Capability-style scoping.** `net.scoped(ServiceId::LlmAnthropic) -> ScopedClient` can only reach the hosts registered for that service and only when the service is enabled. Adapters receive a `ScopedClient`, never the root client.
- **Compile-time isolation:**
  - `deino-stt` and `deino-audio` don't depend on `deino-net` or `reqwest`. A CI step runs `cargo tree -p deino-stt -e normal -i reqwest`, which must find nothing.
  - clippy `disallowed-types` bans `reqwest::Client` and `ClientBuilder` everywhere else.
- **Egress log** is an in-memory ring buffer plus an optional table (time, service, host, bytes, no bodies). Offline mode is a flag checked in `ScopedClient::send`.
- **CSP:** `connect-src 'self' ipc: http://ipc.localhost asset:`. Remove the `localhost:11434/5167/8178` entries.
